# 阶段 2 · 标定

> **目标：让机器人知道「0 在哪」「正转是正还是负」「能转到哪」。**
> 三件事，一个都不能跳。

---

## 为什么这一步最容易被低估

> **因为在仿真里，这三件事都是「自动正确」的。**
>
> - 你写个 URDF，零位就是原点
> - 你定义个关节轴，方向就定了
> - 你写个 `range`，限位就有了
>
> **真机上，它们全是未知的。**

**⇒ 标定就是把「仿真里免费得到的东西」，在真机上重新建立一遍。**

---

## 一、零位标定

### 1.1 零位是什么

**每个关节的 0 点** —— 即「电机反馈读数为 0 时，机械上处于什么姿势」。

**❌ 常见误解**：以为零位是「腿伸直」。
**✅ 实际**：零位是**你指定的任意一个方便姿势**，通常选**屈膝站立位**（`joint_default_angle`），
因为那是机器人工作时的中间位置。

**【实测】DM10 的默认角**：
```yaml
joint_default_angle: [-0.4, 0.0, 0.0, 0.8, -0.4,   # 左腿 l1..l5
                      -0.4, 0.0, 0.0, 0.8, -0.4]   # 右腿 r1..r5
```

### 1.2 ⚠️ 标定前必须做的安全动作【官方】

> **此阶段涉及电机扭矩的瞬间输出与位置闭环，必须配合安全吊架将机器人悬空进行。**

> **标零前提：在执行 Reset 动作前，必须确认所有电机已完成绝对零位标定。**
> **电机未标零前不要进行 reset 操作！reset 推荐使用吊架在空中进行。**

> **姿态匹配：在按下手柄 "A" 键进行 Reset 时，操作员需手动干预机器人肢体，**
> **保证机器人当前的物理姿态与设定的 Reset 零位姿态尽可能相近。**

> **位置突变警告：若物理姿态与零位偏差过大，Reset 瞬间会产生极大的阶跃响应（动作突变），**
> **极易扯坏电机减速器与结构件。**

**⇒ 这三条合起来是一个完整的安全逻辑**：

```
未标零 → 禁止 Reset
标了零 → Reset 前也要手动摆正姿态
姿态差太大 → 阶跃会扯坏减速器
```

### 1.3 两种标定方式

| 方式 | 适用 | 特点 |
|---|---|---|
| **A. 服务式** | 整机、快速 | `ros2 service call /set_zeros`（**对全部电机广播**）|
| **B. 脚本式** | 逐台、可控 | `scripts/set_zero.py`（**逐台确认**）|

#### 方式 A：服务式【官方】

```bash
# 顺序很重要
1. ./tools/start_robot.sh
2. source /opt/ros/humble/setup.bash && source install/setup.bash
3. ros2 service call /init_motors  std_srvs/srv/Trigger
4. 确认机器人处于目标零位，且此时没有运行推理
5. ros2 service call /set_zeros    std_srvs/srv/Trigger
```

> ⚠️ **第 4 步的两个前提**：① 姿态是目标零位 ② **没有在跑推理**
> （`/set_zeros` 在推理运行时会**直接拒绝**）

#### 方式 B：脚本式

**【实测】`roboparty_deploy/scripts/set_zero.py` 的流程**：

```
读 YAML → 建电机列表 → 全局确认（按 Enter）
  → 串行逐台：
       init_motor() → 切 MIT 模式 → 进「纯阻尼」循环
       （kp=0, kd=1 → 关节松软，可手动摆动）
       实时显示 pos / error_id
       按键：Enter = 标零 ／ 空格 = 跳过 ／ Ctrl+C = 中断
  → 汇总打印
```

**它的两个设计细节值得学**：
1. **纯阻尼模式**（kp=0, kd=1）—— 关节松软，**可以手动摆位**
2. **非阻塞按键** —— 不用每台都重跑脚本

### 1.4 ⚠️ 现有脚本的一个缺陷

> **【实测】`set_zero.py` 把 `set_motor_zero()` 的返回值丢弃了**（`:104`）。
>
> ⇒ **「硬件标零失败」在这个脚本里看不出来**，
> 只在 C++ 层打 warn（`dm_motor_driver.cpp:198-204`）。

**⇒ 用 `scripts/joint_test.py` 复核标定结果**（见阶段 3）。

### 1.5 标定后的核验【官方】

**两个终端**：

```bash
# 终端 1
source /opt/ros/humble/setup.bash
ros2 topic echo /joint_states

# 终端 2
source /opt/ros/humble/setup.bash
ros2 service call /refresh_joints std_srvs/srv/Trigger
ros2 service call /read_joints    std_srvs/srv/Trigger
```

**标定判断**（原文）：
> 稍等片刻，第一个终端会打印出当前关节角度与零点的偏差，
> **如果偏差都在 `joint_default_angle` 附近，可进行 reset 操作。**
> 如果偏差较大，请检查电机是否标零或标零操作是否正确。

### 1.6 ⚠️ 腰部 yaw 的方向陷阱【官方】

> ⚠️ **本项目没有腰部电机**（腰段刚性一体），**这一节仅作知识参考**。
> 官方整机的腰 yaw 关节有专门的标定方向要求 —— 若将来加装腰部，回到本节。

> **特别注意腰部 yaw 关节使用限位块标定时的标定方向，**
> **应为下半身不动时上半身逆时针旋转至限位块处。**

**【实测】rpo（含腰的机型）配置里对应的 `motor_zero_offset` 第 13 项是 `2.093`**：

```yaml
# 两种标定方式对应不同的配置值（仅适用于有腰部的机型）
- 将腰部 yaw 转至限位块处标定：保留 2.093
- 使用打印件固定腰部 yaw 标定：改为 0.0
```

> **⇒ 标定方式变了，配置值必须跟着变。这是"配置与标定方式耦合"的典型。**

## 二、方向标定

### 2.1 方向是什么

**电机正转，对应的关节是往哪转。**

**为什么会有方向问题**：
- 电机安装时可能转 180° 装
- 左右腿是对称的，同一方向定义下会得到相反的物理方向

**【实测】DM10 的 `motor_sign` 全是 1**（左右腿各自编号，物理上已对齐）；
**rpo 有 `-1`**（23 关节，存在反向安装的关节）。

### 2.2 怎么验证

**判据非常直接**：

```
给一个小的正向目标（如 +0.1 rad）
  → 看关节往哪个方向动
  → 与你的预期一致吗？
```

**⚠️ 单电机层的坑**：
**【实测】`motor_sign` 只在 `RobotInterface` 层生效，`motors_py` 层读到的是原始硬件符号。**

**⇒ 如果你用 `motors_py` 写测试脚本，必须自己比对「命令符号 vs 反馈位移符号」。**

### 2.3 更细的验证：右手定则

对每个关节，按 URDF 里定义的**旋转轴**，用右手定则判断：

```
轴 +z（如膝关节 hinge axis="0 0 1"）
  → 正向旋转 = 从 +z 方向看逆时针
```

**【实测】DM10 的关节轴**（来自 MJCF）：

| 关节 | 轴 | 范围 |
|---|---|---|
| l1 (髋 pitch) | `(0,1,0)` | [-1.05, 1.05] |
| l2 (髋 roll) | `(1,0,0)` | [-0.52, 0.785] |
| l3 (髋 yaw) | `(0,0,1)` | [-0.52, 0.785] |
| l4 (膝) | `(0,1,0)` | **[-0.3, 2.3562]** |
| l5 (踝) | `(0,1,0)` | [-1.047, 0.3] |

## 三、限位

### 3.1 两层限位

| 层 | 是什么 | 谁管 |
|---|---|---|
| **软限位** | 配置里的 `joint_limits` | 代码检查（越限→急停）|
| **硬限位** | 机械限位块 | 物理挡住 |

**两者都要有。** 硬限位是最后一道防线。

### 3.2 ⚠️ 现有实现的三个缺口【实测】

| # | 缺口 | 后果 |
|---|---|---|
| **1** | **只检实测、不限制下发目标** | 代码只在 `obs_manager.cpp:225-231` 检查**实测**角度越限；**不对下发的目标做裁剪** |
| **2** | `joint_limits` 默认是**空** `{}` | 未配置则**整段检查消失**（静默）|
| **3** | 部分配置把限位设成 **±3.14** | **等于关掉这个保护**（如 `parkour.yaml`）|

> ⚠️ **第 3 条尤其要注意**：配置里写着"有限位"，实际是"无限位"。

### 3.3 怎么测

**逐关节慢速扫行程**，看：
1. 到达限位前有没有异常（异响、卡顿）
2. **软限位触发时的角度**与配置是否一致
3. 硬限位是否真的挡得住

**⚠️ 安全**：**扫行程时必须空载 + 有人盯着**，且从**小幅度**开始。

```bash
# 用 joint_test.py 做慢速行程扫描
python3 scripts/joint_test.py --config <robot.yaml> --joint 3 --sweep 0.1
```

## 四、⭐ 过关判据

| # | 判据 | 怎么测 |
|---|---|---|
| **1** | **把机器人摆成"腿伸直站立"，所有关节角都接近 0（或默认角）** | 读 `/joint_states` |
| **2** | **推一下某条腿，它对应的角度变大而不是变小** | 手动推 + 读数值 |
| **3** | **每个关节在软限位内都能自由转动，不撞硬限位** | 慢速扫行程 |

> ⭐ **第 2 条是方向的最终判据。**
> 如果推一下读数变小 —— **方向反了**，或者**零位错了**。

## 五、标定结果要落盘

> ⚠️ **【实测】现有脚本一律只 print，不落盘。**
> `set_zero.py` 标完零只打印到 stdout，不写文件、不写日志。

**⇒ 这是新工具要补的：标定结果必须留证据。**

**为什么重要**：
- 电机换过零位后，**新零位和旧的可能不一致**
- 没有记录，你无法判断"这次为什么和上次不一样"

**记录模板**：
```json
{
  "date": "2026-09-15",
  "robot": "dm10",
  "method": "script" | "service",
  "joints": [
    {"index": 0, "name": "leg_l1", "motor_id": 1, "bus": "can2",
     "zero_offset": 0.0, "sign": 1, "verified": true}
  ],
  "notes": "右腿 ID=1 电机返修装回后重新标定"
}
```

## 六、常见症状

| 症状 | 最可能原因 |
|---|---|
| 一上电就往一边倒 | 零位错了，或某关节方向反了 |
| Reset 时剧烈动作 | **物理姿态与零位差太大**（官方明确警告）|
| 某个关节转到头了还在使劲 | 软限位没配（空 `{}`）或配成了 ±3.14 |
| 标完零后发现偏差仍在 | `set_motor_zero()` **失败但被丢弃了返回值** |
| 换电机后行为变了 | **零位变了** —— 这在 DM10 上真实发生过（右腿电机返修）|

> ⚠️ **最后一条尤其重要**：
> **硬件维修窗口会改变零位。**
> 【实测】DM10 的右腿 ID=1 电机在返修，**装回来之后零位很可能和之前不一致**。
> ⇒ 这也意味着：**训练时要加「零位偏置」的域随机化**，否则策略上真机会直接偏。
