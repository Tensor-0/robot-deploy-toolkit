# 阶段 3 · 单关节稳停

> **目标：让每个关节都能「给定目标 → 平稳过去 → 停住 → 不抖」。**
> 这一步的产出不是一个能走的机器人，而是一个**已知正确的关节层基线**。

---

## 一、为什么这一步不能跳

### 1.1 「稳停」是个独立目标

**新手直觉**：给个目标角，它到了就完事了。

**实际发生的**（目标角都"到了"，但状态完全不同）：

| 现象 | 原因 |
|---|---|
| 到位了但**在抖** | kp 太高（过冲后反复修正）|
| 到位了但**嗡嗡响** | kd 太低（高频振荡）|
| 慢慢晃过去，**停不住** | kd 太高（响应迟钝）|
| **差一点点**到不了 | 前馈/重力补偿不足，静差 |
| 受一点力**就掉下去** | kp 太小（撑不住负载）|

> **⇒ 「走到了」和「站好了」是两件事。**
> 打个比方：让一个人走到墙边 —— **走到**是位置对了；**站好**是不来回晃、不靠墙发抖、推一下能回来。

### 1.2 为什么必须"先单个，再多关节"

**三个理由**：

**理由 1：多关节时问题会互相掩盖**

假设 10 个关节里有 1 个 kp 不对：

| 场景 | 现象 |
|---|---|
| **单独测那 1 个** | 抖得很明显 → **一眼看出是它** |
| **10 个一起上** | 整机在晃，**你说不清是哪个** |

**理由 2：单关节时负载是已知的**

| | 单个关节 | 多关节一起 |
|---|---|---|
| 重力负载 | **固定** | **变化**（姿态一变，每个关节的负载全变）|
| 其他关节的力 | 没有 | 会通过连杆传过来 |

> **⇒ 单测调好的 kp，整机上可能完全不够。**

**理由 3：它是「归因」的基石**

> **"这 10 个关节单独测时都是好的"** —— 这句话是一个**基线**。
>
> 有了它，上机出问题时可以二分：
> - 单测好的 + 整机坏 → **问题在耦合/协调层**（策略、时序、负载分配）
> - 单测就坏 → **问题在关节层**（kp/kd、零位、电机）
>
> **没有这个基线，你只能在两个假设之间瞎猜。**

### 1.3 ⚠️ 别在这里过度打磨

**因为单关节的"完美 kp"在整机上往往不适用**（负载变了）。

> **这一步的合理目标是**：
> **不是"找到最优 kp/kd"，而是"确认每个关节都健康、方向对、零位准、能受控"。**

**一个实用的判据**：

> **如果某个关节的 kp 需要调到和别的关节差很多才能稳，那多半不是 kp 的问题** ——
> **是零位错了、方向反了、或者机械上有别劲。**
> **这时候应该回去查阶段 2，而不是继续调 kp。**

## 二、⭐ 这一阶段最大的坑：仿真 PD ≠ 真机 PD

**【文献说】论文原话：「大增益在仿真里能稳定，但在真机上会振荡。」**

| | 仿真（MuJoCo `<position>`）| 真机（DM MIT 模式）|
|---|---|---|
| PD 在哪算 | **物理引擎内部** | **电机固件里** |
| 用什么状态 | **步末状态**（隐式约束 `e_{n+1}=0`）| **当前状态** |
| 效果 | 大增益也稳 | **大增益会振荡** |

> **⇒ 你在仿真里调好的 kp=30，搬到真机上会振荡。**
> **别从仿真的值起步。**

**【实测】DM10 的官方起点值**（来自达妙 sim2real 配置）：

```yaml
kp: [16, 20, 20, 18, 20, 16, 20, 20, 18, 20]
kd: [3.0, 3.0, 3.0, 3.0, 3.0, 3.0, 3.0, 3.0, 3.0, 3.0]
```

> **这不是猜的，是经过验证的。从这里起步。**

## 三、逐关节测试（实操）

### 3.1 先跑只读模式

```bash
# 最安全：不发任何目标，只读状态
python3 scripts/joint_test.py --config <robot.yaml> --readonly
```

**看什么**：
- 每台电机能不能读到位置
- 温度正常吗
- **错误码**（0=失能 / 1=使能 / ≥8=故障）

> ⚠️ **`err=1` 不是错误，是「使能」**。这是 DM 协议最容易误判的地方。

### 3.2 再跑小幅测试

```bash
python3 scripts/joint_test.py --config <robot.yaml> --amplitude 0.1 --out results/joint_test.json
```

**它的安全设计**（这也是为什么现有工具不够用）：
- **先读当前位置**，从那里开始（不是从 0）
- **每步 Δq 限幅**（默认 0.01 rad/步）
- **平滑过渡**（默认 1.5s，避免阶跃）
- **检测错误码即停**
- **finally 里全部失能**
- **结果落盘 JSON**

### 3.3 结果怎么读

```json
{
  "index": 3, "motor_id": 4, "interface": "can2",
  "q_initial": 0.8012, "q_final": 0.9015,
  "tracking_err_max": 0.0123,
  "status": "ok",
  "error_id": 0, "temp": 32.5
}
```

| 字段 | 判读 |
|---|---|
| `tracking_err_max` | **> 0.05 rad 就要查**（跟踪差）|
| `status` | `ok` / `tracking_poor` / `readonly` |
| `error_id` | **0 或 1 正常**；≥8 是故障 |
| `temp` | 高于 70℃ 要留意 |

## 四、kp/kd 整定（实操）

### 4.1 为什么需要专门的工具

> **【实测】现有部署仓库没有任何时序记录** ——
> 无时间戳、无采样缓存、无 CSV。
> **⇒ 调 kp/kd 只能靠肉眼，看不出超调和振荡。**

`gain_tune.py` 补上了这块。

### 4.2 ⚠️ 两个必知的坑（脚本会自动警告）

| # | 坑 | 后果 |
|---|---|---|
| **1** | **增益被静默 clamp**：kp ∈ [0,500]、kd ∈ [0,5] | 超出的**被削平且不报错** —— 你以为加了，其实没加 |
| **2** | **kd = 0** | 说明书明确：**会震荡失控** |

### 4.3 怎么扫

```bash
# 扫 kp（kd 固定 3）
python3 scripts/gain_tune.py --config <robot.yaml> --joint 3 \
    --sweep kp --values 10,16,20,30,40

# 扫 kd（kp 固定 20）
python3 scripts/gain_tune.py --config <robot.yaml> --joint 3 \
    --sweep kd --values 0.5,1,3,5 --kp 20
```

**输出**：`results/gain_tune_<joint>.json`（完整轨迹）+ `.csv`（可直接画图）

### 4.4 怎么判读

| 现象 | 判断 |
|---|---|
| **超调 > 20%** | kp 偏高 |
| **纹波大 + 嗡嗡声** | kd 偏低（但**别设 0**）|
| **上升慢、反应迟钝** | kd 偏高，或 kp 偏低 |
| **稳态误差大** | 前馈/重力补偿不足，**不是 kp 的问题** |

### 4.5 推荐的整定顺序

```
1. 悬空单关节，从官方值起步（kp=16-20, kd=3）
2. kp 从小往大试，找到「能撑住且不抖」的区间
   → 下界：撑不住 / 响应太慢
   → 上界：开始出现高频振荡
3. 取区间中间偏下的值
4. 再调 kd：从当前值微调，到振荡消失
   ⚠️ 不要设 kd = 0
5. 用手推一下，验证能回弹
```

## 五、过关判据

| # | 判据 | 怎么测 |
|---|---|---|
| **1** | 给定目标 → **平稳过去，不振荡** | 目视 + 听声音（嗡嗡 = 高频振荡）|
| **2** | 到位后**误差小且稳定** | 读实际角 vs 目标角，差值**小且不随时间变** |
| **3** | **外力扰动后能弹回** | 用手推一下，松开，应回到原位 |
| **4** | **保持 30 秒不漂** | 看是否缓慢漂移（漂 = 重力补偿不足）|

> ⚠️ **第 4 条特别注意**：**"停住了"和"停稳了"是两回事** ——
> 短时间看是停住的，但可能在以极慢的速度往下沉（重力静差）。

**跑完所有关节后**，你应该有一份 JSON，`summary.ok` 覆盖全部关节。

## 六、⚠️ 这一步「过关」不等于「能站」

**必须说清楚，否则容易误解。**

**还差三件事**：

| 差什么 | 说明 |
|---|---|
| **平衡** | 单关节不需要平衡，整机站立需要（重心投影必须在支撑多边形内）|
| **耦合** | 10 个关节的力会互相传导，单测时不存在 |
| **负载变化** | 整机姿态一变，每个关节的负载大小和方向都变 |

> **阶段 3 = 确认每个轮子都能转、能刹。**
> **阶段 5 = 确认这辆车能直线开。**
>
> **轮子好 ≠ 车能开**（还有转向、悬挂、四轮对齐）。
> **但轮子不好，车一定开不了。**

## 七、常见症状

| 症状 | 最可能原因 | 去哪查 |
|---|---|---|
| 电机不动，也不报错 | **模式没切**（首次调用只切模式，不发目标）| [通讯打通 §7](../01-通讯打通/0-index.md) |
| 一直读到同一个错误 | `error_id` 只增不减 | [通讯打通 §4.1](../01-通讯打通/0-index.md) |
| 读数乱跳 | 静止时速度字段无意义 | [通讯打通 §4.3](../01-通讯打通/0-index.md) |
| 某个关节特别难调 | **零位/方向有问题**，不是 kp | [标定](../02-标定/0-index.md) |
| 加了 kp 但没变化 | **被 clamp 削平了**（上限 500）| 本文 §4.2 |
