# 安全须知（首次上机必读）

> **如果你今天第一次上机，读完这一页再动手。**
>
> 本章依据：**《萝博头原型机（RoboParty Roboto Origin）安全操作指南 V1.1.1》**
> （生效日期 2026-03-16）【官方】
> 加上 DM10 项目上的实测补充。【实测】

---

## 一、两条总纲【官方】

### 1. 高动态风险 —— 必须用吊架

> **机器人在步态调试中存在极高的失稳倾倒风险。**
> **任何悬空标零或步态推理测试，必须在配备承重安全吊架（防摔保护）的受控场地内进行。**

**这一条没有例外。** 不是"注意安全"，是**"必须配备设备"**。

### 2. 物理急停至上 —— 先软后硬

> **遇到任何不可控的关节抖动、步态偏离或结构干涉，**
> **请立即按下遥控手柄的 "X" 键触发软件失能；**
> **若软件失控，请立即拍下物理急停开关切断主电源。**

**注意这个顺序**：先 X（软件），软的不行再拍物理急停。
**但物理急停必须在手边** —— 因为「软件失控」正是你可能遇到的情况。

## 二、上电前必做的三项核验【官方】

### 2.1 电源与电池

> **电压阈值检查：检查电池组当前电压。当电池电压低于 50V 时，请立即进行充电。**
> **严禁在欠压状态下运行，否则将触发欠压保护，导致机器人运行中途行为异常或突然掉电跌倒。**

⚠️ **这条新手绝对想不到** —— 欠压不是"跑得慢一点"，是**运行中途突然掉电，机器人直接摔倒**。

### 2.2 机械结构 —— 重点查脚踝

> **关键紧固件检查：重点核对脚踝连杆的紧固状态。**
> **若脚踝连杆松动或未达到规定扭矩，将直接导致脚踝发力异常，**
> **机器人在推理阶段将无法正常站立并可能损坏结构件。**

⚠️ **为什么是脚踝**：脚踝承受最大的冲击和扭矩，而且它是**离地最近、最容易松的连杆**。
**松动的表现是"站不住"** —— 很容易被误判成"策略不行"。

### 2.3 通讯链路 —— 手柄模式

> **手柄状态检查：检查遥控手柄，按 home 键将手柄与接收器配对连接，**
> **此时确保手柄模式处于 "Xinput" 模式。**

⚠️ **模式不对 = 机器人收不到指令**，而且在软件里看不出来（`/joy` 话题就是没数据）。

## 三、使能与零位初始化（高危阶段）【官方】

> **此阶段涉及电机扭矩的瞬间输出与位置闭环，必须配合安全吊架将机器人悬空进行。**

### 3.1 状态使能

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 主电源上电 | 全身电机指示灯**默认红色（失能）** |
| 2 | 按遥控器 **"X"** 使能 | **目视检查全身指示灯是否变为绿色** |
| 3 | ⭐ **再按一次 "X" 测试失能** | 指示灯应切回红色 |
| 4 | 确认失能正常后，**重新使能** | 绿灯 |

> ⭐ **第 3 步是最容易被跳过、也最该做的一步** ——
> **它是在验证"你的急停还能用"**。等真的出事时才发现 X 键没反应，就晚了。

### 3.2 零位偏差核验

**姿态预调**：
> 电机使能后，可以**手动调整电机**使机器人姿态与 `joint_default_angle` 时姿态相近，
> **防止动作突变，损坏电机与结构件。**

**终端核验**（两个终端）：

```bash
# 终端 1：订阅关节姿态
source /opt/ros/humble/setup.bash
ros2 topic echo /joint_states

# 终端 2：刷新并读取
source /opt/ros/humble/setup.bash
ros2 service call /refresh_joints std_srvs/srv/Trigger
ros2 service call /read_joints std_srvs/srv/Trigger
```

**标定判断**（原文）：
> 稍等片刻，第一个终端会打印出当前关节角度与零点的偏差，
> **如果偏差都在 `joint_default_angle` 附近，可进行 reset 操作。**
> 如果偏差较大，请检查电机是否标零或标零操作是否正确。

⚠️ **特别注意腰部 yaw 关节**（原文）：
> 使用限位块标定时的标定方向，应为**下半身不动时上半身逆时针旋转至限位块处**。

### 3.3 悬空 Reset 操作规范

> **标零前提：在执行 Reset 动作前，必须确认所有电机已完成绝对零位标定。**
> **电机未标零前不要进行 reset 操作！reset 推荐使用吊架在空中进行。**

> **姿态匹配：在按下手柄 "A" 键进行 Reset 时，操作员需手动干预机器人肢体，**
> **保证机器人当前的物理姿态与设定的 Reset 零位姿态尽可能相近。**

> **位置突变警告：若物理姿态与零位偏差过大，Reset 瞬间会产生极大的阶跃响应（动作突变），**
> **极易扯坏电机减速器与结构件。**

⚠️ **这三条合起来是一个完整的安全逻辑**：
```
未标零 → 禁止 Reset
标了零 → Reset 前也要手动摆正姿态
姿态差太大 → 阶跃会扯坏减速器
```

## 四、推理与动态运行【官方】

### 4.1 落地与位姿准备

> **平稳落地：Reset 完成后，将机器人从安全吊架上平稳降下。**
> **操作员需观察并确认双脚脚底完全踩实地板，重心分布均匀。**

### 4.2 ⭐ 摇杆死区消除（新手绝对想不到）

> **指令清零：按 "B" 推理前，务必手动全行程拨动左右摇杆，并按压 "LT" 和 "RT" 键数次。**
> **此操作用于消除硬件摇杆死区或漂移，防止残留指令在推理启动瞬间**
> **导致机器人产生非预期的侧偏或冲刺。**

⚠️ **不做这一步的后果**：机器人一启动就**侧偏或冲刺** ——
而且你会以为是策略问题。

**原理**：手柄摇杆有硬件死区和零点漂移，静止时可能输出非零值。
这个残留值在推理启动的瞬间会被当作指令，机器人立刻执行。

### 4.3 节点状态监听与推理启动

> **后台状态确认：操作员必须在上位机终端使用 `screen -r inference_node` 命令，**
> **检查推理节点运行状态。确认无 Error 报错后，方可进行下一步。**

```bash
screen -r inference_node      # 确认无 Error
```

> **启动推理：按下遥控器 "B" 键，正式切入模型推理状态。**
> **此时监护员需密切关注机器人步态，手握吊架控制绳或随时准备按下 "X" 键。**

## 五、异常排查与应急处置【官方】

> **在运行全生命周期内，如遇突发状况，请按以下逻辑处置：**

### 5.1 一键失能（急停）

> **机器人在推理过程中发生任何行为异常（如高频振荡、关节超速、失稳倾倒），**
> **请操作员立即按下 "X" 键切断电机使能。**

**"任何行为异常"包括**：
- 高频振荡（抖动、嗡嗡响）
- 关节超速
- 失稳倾倒
- **以及任何你说不上来但觉得不对的情况**

> **⚠️ 【实测】一个重要的认知**：
> **X 键失能 = 电机卸力 → 站立中执行必然瘫倒。**
> 它不是"让机器人站住"，是"让机器人不再自己动"。
> **所以按 X 之后，机器人会倒下 —— 这就是为什么必须有吊架。**

### 5.2 突然失能后的排查

> **异常掉线排查：如果机器人在推理中发生非人为触发的"突然失能"（瘫软倒地），**
> **请保持现场状态，立即使用 `screen -r inference_node` 进入终端查看报错提示。**

**常见原因**（原文）：
> - **算法层**触发了设定的安全限幅（如关节超限、速度超限）
> - **硬件层**触发了过载、过热或欠压保护

### 5.3 日志留存

> **日志留存：在断开主电源前，建议先导出终端的 Error 日志，以便研发团队定位问题源头。**

⚠️ **日志只在 screen 会话里，关机即失。** 所以这一步不能省。

## 六、【实测】现有代码的安全缺口（这一节不是官方的）

**我们实读 `roboparty_deploy` 代码后发现的、官方指南没覆盖的缺口：**

| # | 缺口 | 后果 | 严重度 |
|---|---|---|---|
| **1** | **IMU 断线会让摔倒保护静默失效** | 四元数 (0,0,0,0) → 归一化 NaN → `gravity_b` NaN → 判据 `NaN > -0.5` 恒为 false → **保护不触发**；且 NaN 会流进策略和动作 | 🔴 |
| **2** | 现有安全机制**全是「退出+失能」，无中间档** | 出事瞬间机器人**瘫软**，对行走中的机器人本身就是风险 | 🔴 |
| **3** | **电机错误码无人消费** | `get_error_id()` 只有定义和 Python 绑定，推理侧从不读；`init_motor()` 的错误码被丢弃 | 🟠 |
| **4** | **温度完全未监控** | 驱动层已缓存，推理侧无读取、无阈值、无降额 | 🟠 |
| **5** | **无 CAN 假死检测** | RX 线程出错仅打日志并静默退出，节点照跑 | 🟠 |
| **6** | **无推理超时保护** | 循环超期只打 WARN，不降级不停机 | 🟡 |
| **7** | 控制指令**不按 `joint_limits` 裁剪下发目标** | 只检实测、不限制目标 | 🟡 |

> **⇒ 这些是"补丁清单"，见 [已知限制](../09-参考/已知限制.md)。**

## 七、一句话总结

> **官方指南的四章，本质上是一句话：**
>
> **把"我以为没问题"的每一个环节，都变成"我确认过"的动作。**
>
> - 我以为电池还有电 → **确认电压 ≥ 50V**
> - 我以为连杆是紧的 → **确认脚踝紧固**
> - 我以为 X 键能用 → **确认按一次真的失能**
> - 我以为摇杆归零了 → **确认全行程拨过**
> - 我以为节点没问题 → **确认 screen 里无 Error**
>
> **每一个"我以为"，都有对应的"我确认过"。这就是安全流程的全部。**
