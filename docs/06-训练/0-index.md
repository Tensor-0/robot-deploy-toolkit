# 阶段 6 · 训练

> **这一章写得短，因为训练本身不是本仓库的重点。**
> 本仓库关注的是「训练产物怎么安全地搬到真机上」。

---

## 一、核心认知：上限在「定任务」那一步

> **训练只是在给定的任务定义下找最优解，
> 它不会质疑任务定义本身。**
>
> **⇒ 你写漏的每一条约束，都是策略的合法自由。**

**打个比方**：
> **奖励表不是"说明书"，是"合同"。**
> 你写什么，策略就按什么执行 —— **包括你没写但也没禁止的部分。**

### 实测佐证

奖励表里 `joint_limit` 权重 **-10.0**，
但**触发率只有 0.2%**、峰值量级 2e-6 —— **完全空转**。

> **⇒ 挂大权重 ≠ 它会起作用。奖励项要"审计"，不能只看配置。**

---

## 二、⚠️ 不要走「加惩罚」这条路

**这条来自调研的硬结论。**

**痛点**：「手工奖励改 5 次，全被 policy 规避。」

**5 个方向独立收敛到同一句话**：

> **问题不在"奖励没调好"，在「用奖励表达约束」这个做法本身。**

| # | 原因 |
|---|---|
| **1** | **奖励可交易，约束不可** —— 惩罚再大只是抬价 |
| **2** | **折扣因子让远期惩罚打折** —— 策略学会"在折扣最低时摔" |
| **3** | **指示函数没有梯度** —— 离撞 1cm 和 1m 的信号**完全一样** |

**⇒ 解法是「换任务表述」，不是「把惩罚调大」**：

| 做法 | 效果 |
|---|---|
| ❌ 告诉策略**别做什么** | 策略在没被禁止的维度上钻空子 |
| ✅ 给一段**参考动作** | **同时**约束所有维度，**没有换路的空间** |

**实测验证**：
- 手工奖励 5 次失败 → 步频 5.5Hz、滑移 0.40
- 换成运动跟踪 → **一次成功**，步频 0.62Hz、滑移 0.11

## 三、训练产物：必须交给部署侧什么

**训练跑完，除了 `policy.onnx`，还要给这些**：

| # | 产物 | 为什么 |
|---|---|---|
| **1** | `policy.onnx` | 当然 |
| **2** | **`run_config.json`** | ⭐ **含 `contract_snapshot`，逐字保存了配置契约** |
| **3** | 训练用的完整 YAML | 复现 |
| **4** | 同种子仿真回放视频 | 出问题时对照 |

> ⭐ **第 2 项最容易被忽略，但它是 `check_contract.py` 的输入。**
> **没有它，就无法自动比对观测契约。**

**好消息**：`run_config.json` 是**自动落盘的**，不用额外做。

```
<UniLab run 目录>/run_config.json
  └── contract_snapshot
        ├── env.observations       ← ⭐ term 顺序
        ├── env.actions
        ├── algo.obs_groups
        └── env.ctrl_dt
```

## 四、⭐ 千万别忘：训练侧的域随机化

**Docker 的坑是：真机上会变的东西，训练时没随机化，策略上真机就废。**

| 该随机化的 | 为什么 |
|---|---|
| **执行器动力学**（PD 增益、动作延迟）| 硬件上策略振荡的**首要驱动因素** |
| 质量/惯量 | 平衡与跟踪裕度 |
| 摩擦 | 足-地接触 |
| **观测噪声**（IMU 噪声、编码器偏置）| 让 actor 输入贴近部署侧传感器行为 |
| 外力 | 对未建模扰动的鲁棒性 |
| **⭐ 关节零位偏置** | **硬件维修会改变零位**（DM10 真实发生过）|

> ⚠️ **最后一条尤其重要**：
> **换电机/返修之后零位会变。** 如果训练时没随机化零位偏置，
> 装回来之后策略上真机会**直接偏**。

---

## 五、⭐ 训练时的动作延迟

**这条和部署直接相关。**

如果训练时假设"动作立即生效"，而真机有延迟 →
**真机上会出现接触振荡 / 动作饱和**。

**怎么建**：给动作加单步或几步延迟，延迟量按**周期占比**设定
（不是照搬文献的绝对 ms 值）。

**实测参考**（本机 250 Hz）：
- 通信延迟抖动：0 – 0.3 ms（周期的 0–7.5%）
- 调度抖动：0 – 0.2 ms（周期的 0–5%）

## 六、训练与部署的交接清单

**训练完成后，逐项确认**：

```
☐ policy.onnx 导出了
☐ run_config.json 里有 contract_snapshot
☐ 记下了 obs 的声明顺序和每段维度
☐ 记下了 action_scale / clip_actions / joint_default_angle
☐ 记下了 kp/kd（是真机的，不是仿真的）
☐ 域随机化覆盖了：PD 增益 / 质量 / 摩擦 / 观测噪声 / 关节零位偏置
☐ 训练时建了动作延迟
☐ 有同种子仿真回放视频
```
