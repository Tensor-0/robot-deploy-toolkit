# 阶段 7 · 上机四步

> **这是整个流程里最危险、也最需要纪律的一段。**
> 前置：[安全须知](../05-安全保底/1-安全须知（首次上机必读）.md) 已读、[PD 站立保底](../05-安全保底/1-安全须知（首次上机必读）.md) 已实现。

## 为什么是「四步」，而不是一步到位

**因为每一步验证的是不同的东西，而混在一起就归因不了。**

来源：【官方】UniLab 部署文档 G1 上机序列 + 【实测】DM10 补充。

```
① 支架上站立     —— 策略运行，但**力矩关闭**。验证：观测管线
② 使能力矩手扶   —— 操作员扶住。          验证：action 映射
③ 龙门架半速     —— 时间速率减半。        验证：闭环稳定性
④ 自由全速       —— 移除龙门架。          验证：真实性能
```

> ⚠️ **原文警告：不要跳过第①步。**
> 轴顺序、关节顺序、`actions` 接线错误，**最容易在这一步暴露**。

---

## ① 支架上站立（力矩关闭）

**做什么**：
- 机器人吊在支架/吊架上
- 推理节点运行，**但电机不使能**（或 kp=kd=0）
- 观察 `/joint_states`、`/imu`、`/action` 三个话题

**验证什么**：
- **观测管线通不通** —— 观测值合理吗？
- **顺序对不对** —— 这是抓 obs 顺序错误的唯一机会

### ⭐ 怎么用这一步抓 obs 顺序错误

**这是本步骤最有价值的用法**（【推断】，基于 obs 语义推导）：

```
静止站立时，各段的"期望量级"：
  ang_vel      ≈ 0        （没在转）
  gravity_b    ≈ (0,0,-1) （直立）
  dof_pos      ≈ joint_default_angle 附近（-0.4, 0, 0, 0.8, -0.4）
  dof_vel      ≈ 0        （没在动）
  last_action  ≈ 0 附近   （还没动过）
  cmd_vel      ≈ 0        （摇杆中位）

⇒ 如果某一段出现了"它不该有的数值"，就是顺序错了。
   典型症状：cmd_vel 段出现 0.8 这样的大数（那是关节角跑进来了）
```

**配合工具**：
```bash
# 部署前先跑契约比对（顺序 + 每段维度 + 可得性）
python3 _dump_obs_manifest.py --run-dir <训练run>              # 在 UniLab 侧，生成清单
python3 scripts/check_contract.py --manifest <obs_manifest.json> \
        --deploy-config <部署yaml>                              # 在本仓库
# ⭐ 清单里的 3 项无源观测会直接 DENY —— 那说明这份策略【不该上机】，
#    先回训练侧换观测集（见 04-模型与契约 §4.4），别在这里绕。
```

## ② 使能力矩，手扶

**做什么**：
- 机器人仍在支架下，但**力矩打开**
- **操作员扶住机器人**
- 策略输出动作，人观察

**验证什么**：
- **action 映射对不对** —— 策略说"抬左腿"，它真的抬左腿吗？
- **有没有明显的方向错误**（该往前它往后）

> ⚠️ **为什么必须"手扶"**：
> 这一步机器人会**主动用力**。如果有映射错误，它的动作可能很突兀。
> **有人扶住才能及时制止。**
>
> ⭐ **这也是为什么要先做 PD 站立保底** ——
> PD 站立下机器人是"僵直可控"的，手扶得住；
> 直接上 RL 策略，它可能跟你较劲，你扶不住。

**操作要点**（【官方】官方指南原文精神）：
- 使能前先手动把姿态摆到接近 `joint_default_angle`
- 确认双脚踩实、重心均匀

---

## ③ 龙门架半速

**做什么**：
- 仍在龙门架保护下
- **时间速率减半**（`dφ/dt` 减半 —— 参考运动/指令速度减半）

**为什么减半**：
> 速度减半时，**单位时间内积累的误差也减半**。
> 如果策略有问题，你有**两倍的反应时间**去按急停。

**验证什么**：
- **闭不闭得住环** —— 它能跟踪上指令吗？
- **有没有缓慢发散**（慢慢往一边偏）

**【推断】怎么减半**：取决于策略类型
- 运动跟踪类：降低参考帧推进速度
- 速度指令类：把 `cmd_vel` 的限幅临时调小（如 `clip_cmd` 减半）

---

## ④ 自由全速

**做什么**：
- **移除龙门架**
- 全速运行

**前提**：前三步都通过。

**此时的安全网**：
- PD 站立保底（随时可切）
- 物理急停（手边）
- 一个人盯着

## ⭐ 每一步都要记录什么

> 【官方】"为每一步记录**完整的观测向量**、**完整的动作向量**与**墙钟**。
> 把第一段硬件观测窗口与用同一份 owner YAML 构建的仿真回合作对比 ——
> **这个 diff 比任何奖励检查都更快定位单位、坐标系与顺序错误。**"

**记录模板**见 [`templates/上机记录模板.md`](../../templates/上机记录模板.md)。

**最小记录集**：
```
1. 时间 / 机型 / 策略版本（onnx 哈希）/ git commit
2. 完整 obs 向量 + action 向量 + wall_clock
3. 训练用的 config.yaml
4. 部署侧 config（obs_layouts / action_scale / joint_limit）
5. 同种子仿真回放视频
6. 异常现象 + 时间点
7. 结论 / 下次试什么
```

## 每步的「过关判据」速查

| 步 | 过关判据 |
|---|---|
| ① | 三个话题都有数据；**各段数值量级合理**；`gravity_b ≈ (0,0,-1)` |
| ② | 策略动作**方向正确**；无剧烈突兀动作；手扶得住 |
| ③ | 能跟上减半速的指令；**不缓慢发散**；能持续跑完一个完整周期 |
| ④ | 全速下步态稳定；能正常起停；**急停可用** |

## 出问题时怎么办

| 现象 | 最可能的原因 | 去哪查 |
|---|---|---|
| ① 就有异常数值 | **obs 顺序错** | [观测契约对齐](../04-模型与契约/0-index.md) |
| ② 动作方向反了 | `motor_sign` / `usd2urdf` 错 | [方向检查](../02-标定/0-index.md) |
| ② 动作幅度不对 | `action_scale` / `joint_default_angle` 没对齐 | [观测契约对齐](../04-模型与契约/0-index.md) |
| ③ 缓慢发散 | PD 增益不匹配 / 观测有偏 | [kp/kd 整定](../03-单关节稳停/0-index.md) |
| ③ 高频振荡 | **训练时动作延迟建得不对** 或 kp 过高 | [故障排查](../08-故障排查/0-index.md) |
| ④ 立即摔倒 | **几乎总是三者之一**：关节顺序 / action 缩放单位 / 观测布局 | [故障排查](../08-故障排查/0-index.md) |

## 一句话总结

> **四步的意义，是让"失败"发生在可控的范围内。**
>
> **每一步只验证一件事，所以每一步失败你都知道是哪里错。**
> **如果跳过某一步，你就失去了那个诊断能力。**
