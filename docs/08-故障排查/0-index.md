# 阶段 8 · 故障排查（症状索引）

> **出问题时先来这里。** 按「你看到的现象」查，不按「问题在哪一层」查。
>
> 格式：**症状 → 30 秒判据 → 最可能原因 → 详细**

---

## 怎么用这一页

**先看「30 秒判据」那一列** —— 每条都是一条命令或一个肉眼可查的现象。
判据能排除一半的可能，剩下再去看详细。

---

## 一、通信层

### 发得出去，收不回来，而且不报错

| | |
|---|---|
| **30 秒判据** | `candump can0`（或 `can1`）没输出，但发指令时电机有反应 |
| **最可能原因** | **socket 没开 `CAN_RAW_FD_FRAMES`** |
| **详细** | [通讯打通 §1.3](../01-通讯打通/0-index.md) |

> ⚠️ **这是最恶心的一个**：TX 完全正常、零报错、RX 全静默。
> 达妙固件把所有帧标成 FD 帧，内核只把 `canfd_frame` 投递给启用了该选项的 socket。

### 完全收不到任何数据

| | |
|---|---|
| **30 秒判据** | 连一帧都没有；`ip -details link show can0`（或 `can1`）看 bitrate |
| **最可能原因** | ① 反馈帧 ID 认错 ② bitrate 不对 ③ 总线没 UP ④ **终端电阻不对** |
| **详细** | [通讯打通 §2.3](../01-通讯打通/0-index.md) · [接线速查 §2](../assets/CAN接线速查.md) |

> ⚠️ **反馈帧仲裁 ID 恒为 `0x000`**，电机身份藏在 **D0 低 4 位**。
> 如果按"can_id = 电机 ID"去分发，永远收不到。

### ⭐ 通信时好时坏 / 高速丢帧

| | |
|---|---|
| **30 秒判据** | 数一下总线上有几个 120Ω 终端电阻（**应该正好 2 个**）|
| **最可能原因** | **终端电阻缺失或过多** |
| **详细** | [接线速查 §2](../assets/CAN接线速查.md) |

> ⚠️ **这是我们早期文档完全没有的一类故障。**
>
> | 现象 | 原因 |
> |---|---|
> | 时好时坏 | **电阻缺失** → 信号反射 |
> | 完全不通 | **电阻过多**（>2 个）→ 总线负载过大 |
> | 高速丢帧 | 电阻**不在物理两端** |
>
> **⇒ CAN 通信出问题时，先数终端电阻，再查别的。**
>
> **注意**：【官方】「两手臂末端总共只需开一个终端电阻」——
> 说明电阻是**可以在电机侧开/关的**，换电机后必须核对。
> ⚠️ **本项目无手臂**，但这条规则**对腿部同样适用**（换腿电机后要核对电阻状态）。

### 电机不动，也不报错

| | |
|---|---|
| **30 秒判据** | 打印 `get_motor_control_mode()`，看是不是 MIT |
| **最可能原因** | **模式没切** —— 首次调用只切模式、当次不发目标 |
| **详细** | [通讯打通 §7](../01-通讯打通/0-index.md) |

> **修法**：脚本里必须先 `set_motor_control_mode(MIT)`，再进循环发命令。

### 第二个电机收不到反馈

| | |
|---|---|
| **30 秒判据** | 检查同一总线上有没有重复 ID |
| **最可能原因** | **同总线同 ID 冲突** —— 第二个实例静默顶掉第一个的回调 |
| **详细** | [通讯打通 §4.2](../01-通讯打通/0-index.md) |

### 速度读数乱跳

| | |
|---|---|
| **30 秒判据** | 电机静止时读速度，看是不是在 3855/3854/0 之间跳 |
| **最可能原因** | **静止时该字段物理上无意义**（不是故障）|
| **详细** | [通讯打通 §4.3](../01-通讯打通/0-index.md) |

### 一直读到同一个错误码

| | |
|---|---|
| **30 秒判据** | `clear_motor_error()` → 等 0.1s → `refresh_motor_status()` → 再读 |
| **最可能原因** | **`error_id` 只增不减** —— 直接读会读到历史错误 |
| **详细** | [通讯打通 §4.1](../01-通讯打通/0-index.md) |

## 二、标定层

### 一上电就往一边倒

| | |
|---|---|
| **30 秒判据** | `ros2 topic echo /joint_states`，看各关节角是否接近 `joint_default_angle` |
| **最可能原因** | ① 零位错了 ② 某关节方向反了 |
| **详细** | [标定](../02-标定/0-index.md) |

### Reset 时剧烈动作

| | |
|---|---|
| **30 秒判据** | 看按 A 之前，机器人的物理姿态是否接近零位 |
| **最可能原因** | **物理姿态与零位差太大** → 阶跃响应 |
| **详细** | [标定 §1.2](../02-标定/0-index.md) |

> ⚠️ **官方明确警告**：「极易扯坏电机减速器与结构件」。
> **修法**：Reset 前**手动把姿态摆到接近 `joint_default_angle`**。

### 某个关节转到头了还在使劲

| | |
|---|---|
| **30 秒判据** | 看配置里的 `joint_limits` 是不是 `±3.14` 或空 `{}` |
| **最可能原因** | **限位保护被配置值关掉了** |
| **详细** | [标定 §3.2](../02-标定/0-index.md) |

### 换电机后行为变了

| | |
|---|---|
| **30 秒判据** | 对比换之前的零位记录 |
| **最可能原因** | **硬件维修改变了零位** |
| **详细** | [标定 §5](../02-标定/0-index.md) |

> ⚠️ 这在 DM10 上**真实发生过**（右腿 ID=1 电机返修）。
> ⇒ 也意味着训练时要加**零位偏置的域随机化**。

## 三、关节层

### 关节在抖 / 嗡嗡响

| | |
|---|---|
| **30 秒判据** | 听声音；用 `gain_tune.py` 采一条响应曲线看超调 |
| **最可能原因** | ① kp 太高 ② kd 太低 ③ **仿真 PD ≠ 真机 PD** |
| **详细** | [单关节稳停 §2/§4](../03-单关节稳停/0-index.md) |

> ⚠️ **别从仿真的 kp 起步**。仿真里 kp=30 稳，真机上会振荡。

### 加了 kp 但没变化

| | |
|---|---|
| **30 秒判据** | 看 kp 是不是超过 **500**、kd 超过 **5** |
| **最可能原因** | **被静默 clamp 削平了**（不报错！）|
| **详细** | [单关节稳停 §4.2](../03-单关节稳停/0-index.md) |

### 某个关节特别难调

| | |
|---|---|
| **30 秒判据** | 看它需要的 kp 是否和其他关节差很多 |
| **最可能原因** | **多半不是 kp 问题** —— 是零位/方向/机械别劲 |
| **详细** | [单关节稳停 §1.3](../03-单关节稳停/0-index.md) |

## 四、部署 / 契约层（**最容易出事**）

### 一上真机就摔

| | |
|---|---|
| **30 秒判据** | 跑 `check_contract.py` |
| **最可能原因** | **几乎总是三者之一**：<br>① 关节顺序 ② 动作缩放单位 ③ 观测布局 |
| **详细** | [模型与契约](../04-模型与契约/0-index.md) |

> 【官方】原文：「几乎总是以下之一」。
> **先比分项顺序，再比逐项历史顺序。**

### 支架上就有异常数值

| | |
|---|---|
| **30 秒判据** | 静止站立时看各段观测：**某段出现了"它不该有的数值"** |
| **最可能原因** | **观测顺序错位**（维度相同 → 不报错）|
| **详细** | [模型与契约 §5](../04-模型与契约/0-index.md) |

> **典型症状**：`cmd_vel` 段出现 `0.8` 这样的大数 ——
> 那是关节角（`joint_default_angle` 第 4 项）跑进来了。

### 以直腿姿态执行走路

| | |
|---|---|
| **30 秒判据** | 检查部署侧动作后处理有没有加 `joint_default_angle` |
| **最可能原因** | **忘了加默认角** |
| **详细** | [模型与契约 §6.2](../04-模型与契约/0-index.md) |

> 网络输出的是**相对量**（相对屈膝位），加回默认角才是绝对关节角。

### 动作幅度整体偏大/偏小

| | |
|---|---|
| **30 秒判据** | 对比训练侧 `scale` 和部署侧 `action_scale` |
| **最可能原因** | **`action_scale` 不一致** |
| **详细** | [模型与契约 §6.1](../04-模型与契约/0-index.md) |

## 五、运行层

### 推理节点起不来

| | |
|---|---|
| **30 秒判据** | `ulimit -r`（应为 98）|
| **最可能原因** | **实时优先级权限没配** → 线程创建失败 → 节点直接退出 |
| **详细** | [安全须知](../05-安全保底/1-安全须知（首次上机必读）.md) |

### 突然失能（瘫软倒地）

| | |
|---|---|
| **30 秒判据** | **保持现场**，`screen -r inference_node` 看报错 |
| **最可能原因** | 【官方】① 算法层触发安全限幅 ② 硬件层过载/过热/欠压 |
| **详细** | [安全须知 §5.2](../05-安全保底/1-安全须知（首次上机必读）.md) |

> ⚠️ **断电前先导出日志** —— 日志只在 screen 会话里，关机即失。

### 机器人一启动就侧偏/冲刺

| | |
|---|---|
| **30 秒判据** | 回想按 B 之前有没有拨动摇杆 |
| **最可能原因** | **摇杆死区/漂移残留** |
| **详细** | [安全须知 §4.2](../05-安全保底/1-安全须知（首次上机必读）.md) |

> 【官方】要求：按 B 前**全行程拨动左右摇杆 + 按 LT/RT 数次**。

### 欠压/过热保护

| | |
|---|---|
| **30 秒判据** | 电池电压（应 ≥50V）；电机温度 |
| **最可能原因** | 【官方】电池电压 <50V 必须充电 |
| **详细** | [安全须知 §2.1](../05-安全保底/1-安全须知（首次上机必读）.md) |

## 六、⭐ 一个特殊的坑：安全机制在最需要时失灵

### 摔倒检测不触发

| | |
|---|---|
| **30 秒判据** | 看 `/imu` 有没有数据；`gravity_z_upper` 是不是被设成 `1.0` |
| **最可能原因** | ① **IMU 断线 → 四元数 (0,0,0,0) → NaN → 判据恒 false**<br>② 配置里把阈值设成 1.0（单位向量 z 不可能 >1，**等于关掉**）|
| **详细** | [已知限制](../09-参考/已知限制.md) |

> ⚠️ **这是「安全机制在最需要它的时候静默失效」的典型。**
> 更糟的是：**同一时刻策略收到的是 NaN 观测** —— 机器人会拿着 NaN 去控制电机。
