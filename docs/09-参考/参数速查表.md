| 枚举 | 型号 | PosMax (rad) | SpdMax (rad/s) | TauMax (N·m) | OKpMax | OKdMax |
|---|---|---|---|---|---|---|
| 0 | `DM4340P_48V` | 12.5 | 20 | 28 | 500 | 5 |
| 1 | `DM10010L_48V` | 12.5 | 25 | 200 | 500 | 5 |
| **2** | **`DM4340P_24V`** | **12.5** | **6** | **12** | **500** | **5** |

> ⚠️ **`DM4340P_24V` 是 DM10 在用的型号**。
> ⚠️ **⚠️ 本机 4 台实测读到的 VMAX/TMAX 是 10.0 / 28.0，与代码里的 6/12 冲突** ——
> **上电前必须用达妙上位机实读定案**（见 [通讯打通 §3](../01-通讯打通/0-index.md)）。

### DM10 实际配置【实测 `robots/dm10/robot.yaml`】

> 🔴 **2026-09-17 实测更正**：下面 `motor_id` 与 `motor_interface` 两行**以前是错的**。
> 实测：**can0=左腿、can1=右腿**；**CAN ID 从脚踝往上编**（脚踝=1 … 髋=5）。
> ⇒ 必须 `motor_interface: ["can0","can1"]` + `motor_id: [5,4,3,2,1,...]`。
> ⚠️ 写错会让**策略把髋角当脚踝角**，观测/动作双向错位且**不报错**。详见 memory `dm10-frame-alignment`。
> ⚠️ 接口名本身也会漂（板载 CAN 抢 `can0` 时 USB 适配器会变成 can1/can2）——
> 所以脚本一律从 `motor_interface` 读，别写死。

```yaml
motor_id:         [5,4,3,2,1, 5,4,3,2,1]   # ⚠️ 2026-09-17 实测改（旧写 [1,2,3,4,5,...] 是错的）
motor_interface:  ["can0", "can1"]         # ⚠️ 接口名以 robot.yaml 为准；旧写 ["can2","can1"]/["can1","can2"] 都不对
motor_model:      [2 × 10]                 # DM4340P_24V
master_id_offset: 0
motor_zero_offset:[0.0 × 10]

kp: [16, 20, 20, 18, 20, 16, 20, 20, 18, 20]
kd: [3.0 × 10]
motor_sign: [1 × 10]
urdf2motor: [0..9]
```

### MIT 帧格式【实测】

| 字节 | 位域 | 内容 |
|---|---|---|
| D0–D1 | 16 bit | 位置 `p_des` |
| D2 + D3[7:4] | 12 bit | 速度 `v_des` |
| D3[3:0] + D4 | 12 bit | kp |
| D5 + D6[7:4] | 12 bit | kd |
| D6[3:0] + D7 | 12 bit | 力矩 `t_ff` |

### 反馈帧【实测】

| 字节 | 内容 |
|---|---|
| **仲裁 ID** | **恒为 `0x000`**（电机 ID 在 D0 低 4 位）|
| D0 高 4 位 | 状态码（**0=失能, 1=使能**, 8+=故障）|
| D0 低 4 位 | **电机 ID** |
| D1–D2 | 位置 |
| D3 + D4[7:4] | 速度 |
| D4[3:0] + D5 | 力矩 |
| D6 / D7 | MOS 温度 / 转子温度 |

### 特殊帧【实测】

| 功能 | D0..D7 |
|---|---|
| 使能 | `FF×7 FC` |
| 失能 | `FF×7 FD` |
| 保存零点 | `FF×7 FE` |
| 清除错误 | `FF×7 FB` |
| 读参 | `0x7FF` + `id_lo, id_hi, 33, RID, FF×4` |
| 写参 | `0x7FF` + `id_lo, id_hi, 55, RID, v[0..3]` |
| 刷新状态 | `0x7FF` + `id_lo, id_hi, CC, 00, ...` |

### 读参 RID

| RID | 参数 |
|---|---|
| `0x15` | PMAX |
| `0x16` | VMAX |
| `0x17` | TMAX |
| `0x50` | 当前位置 |

> ⚠️ **Python 层读不到**（代码里没有 0x11 回复分支）→ 用达妙上位机。

## 二、IMU（DM-IMU-L1）

| 项 | 值 |
|---|---|
| 传感器 | **BMI088 六轴**（3轴加计 + 3轴陀螺，**无磁力计**）|
| 接口 | USB CDC-ACM，`/dev/ttyACM0` @ **921600** 8N1 |
| 硬件输出频率 | 500 Hz（可配 100-1000）|
| 姿态解算 | 模块内部 EKF |
| 尺寸/重量 | 36×26×9 mm / 11.5 g |
| 安装孔 | 4 × M2.5 |
| **yaw 零漂** | **12.686° / 小时** |
| roll/pitch 零漂 | 0.02° / 0.064° |
| 陀螺/加计带宽 | 116 Hz / 230 Hz |

### 实际帧型【实测】

| RID | 内容 | 说明 |
|---|---|---|
| 1 | 加速度 | m/s²，**含重力**（静止 z ≈ +9.8）|
| 2 | 角速度 | **原生 rad/s** |
| 3 | 欧拉角 | 度 → 驱动转四元数 |
| 4 | 四元数 | ⚠️ **硬件不发** |

> ⚠️ **三处与手册不符**：角速度单位（手册写 °/s）、无四元数帧、无温度帧。
> ⚠️ **晃动时欧拉角会输出 ±inf/nan**。

**帧格式**：`55 AA | ID | RID | DATA | CRC16_LE | 0A`（RID 1/2/3 = 19 字节）

**CRC16**：poly `0x1021`，init `0xFFFF`，
更新式 **`(crc << 1) ^ table[(crc >> 8) ^ byte]`**（⚠️ **不是标准 CCITT 的 `<<8`**）

## 四、观测与动作（DM10）

### 观测【实测】

**训练侧声明顺序**（39 维）：

```
base_ang_vel(3) → projected_gravity(3) → joint_pos(10)
  → joint_vel(10) → actions(10) → command(3)
```

**部署侧 `obs_layouts`**（**应该是这个顺序**）：

```yaml
"ang_vel:3, gravity_b:3, dof_pos:10, dof_vel:10, last_action:10, cmd_vel:3"
```

**名字对照**：

| 训练侧 | 部署侧 |
|---|---|
| `base_ang_vel` | `ang_vel` |
| `projected_gravity` | `gravity_b` |
| `joint_pos` | `dof_pos` |
| `joint_vel` | `dof_vel` |
| `actions` | `last_action` |
| `command` | `cmd_vel` |

### 动作与安全参数【实测】

| 项 | DM10 值 | 备注 |
|---|---|---|
| `action_scale` | **0.25** | 必须与训练侧 `scale` 一致 |
| `clip_actions` | **18.0** | rpo 是 100，parkour 是 10 |
| `clip_observations` | 100.0 | |
| `act_alpha` | **1.0** | ⚠️ **= 不平滑**，建议 0.7-0.9 |
| `joint_default_angle` | `[-0.4, 0, 0, 0.8, -0.4] × 2` | |
| `gravity_z_upper` | **-0.5** | ⚠️ 设成 1.0 = 关掉保护 |
| `clip_cmd` | `[-0.6, 1.0, -0.4, 0.4, -0.8, 0.8]` | vx/vy/ωz 限幅 |
| `frame_stacks` | **1** | 必须与 onnx 匹配 |
