## 一、🔴 安全相关（最要紧）

### 1. IMU 断线会让摔倒保护静默失效

| | |
|---|---|
| **现象** | IMU 断线/未出数时，**摔倒保护不触发**，且策略收到 NaN 观测 |
| **链路** | 四元数初值 `(0,0,0,0)` → 归一化 → **NaN** → `gravity_b = NaN` → 判据 `NaN > -0.5` **恒为 false** |
| **更糟的** | NaN 会穿过 `std::clamp`（`clamp(NaN) = NaN`）**流进策略和动作** |
| **状态** | ⬜ **未修** |
| **修法** | 在 `read_imu()` 后加有效性校验：四元数模长接近 0 或含 NaN → 拒绝并告警 |

> **这是「安全机制在最需要它的时候失灵」的典型。**
> 摔倒检测是唯一的跌倒保护，而 IMU 一断线它就变成哑巴。

### 2. 所有保护都是「退出 + 失能」，没有中间档

| | |
|---|---|
| **现象** | 出事瞬间机器人**瘫软**，对正在行走的机器人本身就是风险 |
| **现状** | 4 项保护（摔倒 / 关节限位 / 掉线 / RT 线程失败）**全是同一策略**：FATAL → shutdown → 失能 |
| **缺什么** | 「保持阻尼」「减速」「**保持站立**」这些中间档 |
| **状态** | ⬜ **未修** |
| **修法** | 引入 **PD 站立保底**：异常时切到固定目标角，而不是直接关机 |

> **这是 `fail-stop` vs `fail-safe` 的区别。**
> 前者是"出事就停"，后者是"出事就进安全态"。

### 3. 电机错误码无人消费

| | |
|---|---|
| **现象** | 电机过流/过温/堵转时，**上层不知道** |
| **证据** | `get_error_id()` 只有定义和 Python 绑定；`init_motor()` 的返回错误码**被丢弃**，还无条件置 `is_init_=true` |
| **状态** | ⬜ **未修** |

### 4. 温度完全未监控

| | |
|---|---|
| **现象** | 驱动层已缓存温度，但推理侧**无读取、无阈值、无降额** |
| **状态** | ⬜ **未修** |

### 5. 无 CAN 假死检测

| | |
|---|---|
| **现象** | RX 线程出错时**只打日志并静默退出**，节点照跑 |
| **缺什么** | bus-off 检测、error-frame 检测、总线恢复 |
| **状态** | ⬜ **未修** |

### 6. 无推理超时保护

| | |
|---|---|
| **现象** | 推理循环超期时**只打 WARN**，不降级、不停机 |
| **状态** | ⬜ **未修** |
| **修法** | 连续 N 次超时 → 卸力 |

### 7. 控制指令不按 `joint_limits` 裁剪

| | |
|---|---|
| **现象** | 代码只检查**实测**角度越限，**不对下发的目标做裁剪** |
| **状态** | ⬜ **未修** |

## 二、🟠 配置层（"看起来有，实际等于关掉"）

| # | 项 | 现象 |
|---|---|---|
| **1** | `gravity_z_upper: 1.0` | 单位向量 z 分量不可能 >1 → **判据永不触发 = 关掉保护** |
| **2** | `joint_limits` 全是 `±3.14` | **等于无限位** |
| **3** | `joint_limits` 是空 `{}` | **整段检查消失**（静默）|
| **4** | `act_alpha: 1.0` | **动作完全不平滑** |
| **5** | `clip_actions: 100.0` | **基本等于不裁剪** |

> ⚠️ **这五条的共同点：配置里"有"，但实际等于没有。**
> **上机前请逐项确认实际生效值。**

## 三、🟠 观测契约

### 1. 观测顺序无编译期保证

| | |
|---|---|
| **现象** | 训练侧和部署侧的 obs 顺序不同时，**运行时不会报错**（只比总元素数）|
| **实例** | DM10 的 `cmd_vel` 训练在第 6 段、部署在第 3 段 |
| **状态** | ⬜ **未修**（但 `check_contract.py` 能检测出来）|
| **根治** | 导出 onnx 时 dump obs 语义清单，部署侧启动时比对 |

### 2. 训练指令覆盖不全

| | |
|---|---|
| **现象** | 训练时**只采纯前进**（`lin_vel_x: [0.3, 0.5]`，vy/ωz 恒为 0）|
| **后果** | 部署侧开放了三轴 → 一推横移或转向，策略进入 **OOD 状态**，反应不可预测 |
| **状态** | ⬜ **未修** |

> **⇒ 这是「配置里能用 ≠ 训练里覆盖过」的典型。**

## 五、🟡 工具链限制（改脚本也绕不过去）

| # | 限制 | 影响 |
|---|---|---|
| **1** | **读量程在 Python 层做不到** | `get_motor_param()` 只发请求，`can_rx_cbk` 无 0x11 分支 → **RID 0x15/0x16/0x17 拿不到** |
| **2** | **写参数通道是 private** | `write_register_dm()` / `save_register_dm()` 只有 private 声明 |
| **3** | **改电机 ID 做不到** | `reset_motor_id()` 对 DM 是空实现 |
| **4** | **同总线同 ID 只能一个实例** | 第二个静默顶掉第一个的回调 |
| **5** | 单电机无温度以外的健康量 | 只有 `get_motor_temperature()` 和 `get_error_id()`；MOS 温度解析了但未暴露 |
| **6** | 整机无逐关节温度/错误 | `RobotInterface` 只有 q/vel/tau |
| **7** | `set_zeros()` 是广播 | 无法"只标某一台"（要用 `motors_py` 逐台）|

## 六、🟡 流程层

| # | 项 | 说明 |
|---|---|---|
| **1** | **观测对齐无自动校验** | 部署侧启动时只比总维度 |
